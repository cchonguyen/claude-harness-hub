- **ADR-010 (2026-11-01):** Harness v3.2 Elephant–Goldfish Model & Neutral Referee Architecture. Structured workflow into distinct cognitive modes: the Elephant (discovery/planning/spec finalization on Sonnet/Opus producing self-contained specs and atomic slices) and the Goldfish (stateless driving/testing/reviews on Haiku/Flash/Sonnet with Opus strictly prohibited). Replaced bureaucratic `.spec/.upshift-auth.json` and `pre-tool-guard.mjs` `exit(2)` checkgates with fact-based `.spec/SCOUT.md` sizing, deterministic level routing in `evaluate-upshift.mjs`, and clear subagent dispatch announcements (`🐘 Dispatching Elephant subagent...`). Consolidated verification and trust into commit trailers (`Referee-Verdict`, `Referee-Tree`, `Referee-Engine`) evaluated by a neutral standalone `referee.mjs` reading scope from `HEAD:.spec/PROGRESS.md` (audit marker threat model ensuring tree and engine integrity without third-party signing), enabling zero-re-verification `/pickup` and zero-token natural lull detection. Collapsed slice conclusion into `finish-slice.mjs`. Split implementation into Slices 3.7–3.11.
- **ADR-011 (2026-11-05):** Dashboard state is derived, never reported. Status: Accepted.
  - Context: agents ran in cloud threads, so state written to gitignored `.spec/STATE.json` was lost with each container. A `Dashboard-Sync` trailer then certified a write nobody could read. Plan v2.2 §1.1 rows 2, 4 and 5 assumed local Mac worktrees.
  - Decision: the dashboard derives slice state from `origin/main` `PROGRESS.md` and GitHub (pull requests, check runs, merge records). Agents do not write dashboard state. Every card shows its source and age. Disagreements between sources are listed, never resolved silently. Local Herdr liveness stays for local panes only.
  - Supersedes: plan v2.2 §1.1 rows 2, 4 and 5 for remote work.
  - Consequences: the `Dashboard-Sync` trailer and `track-slice` command are removed (Slice 9.9). A read-only status page is published by a scheduled GitHub Action every 5 minutes (Slices 9.2.1 and 9.8). The page refreshes every 60 seconds with its age shown. The local Command Center serves the same derived state (9.2.2). The Verified and Accepted stages still need the operator's machine secret and are unchanged.
- **ADR-012 (2026-11-12):** Bug fixes and ad hoc work open an on-the-fly slice. Status: Accepted (owner request, Opus planning approved).
  - Context: outside a slice, a change had to fit the one-file, 25-line quick fix or wait for `/spec`. A larger bug fix was refused or forced through planning. `/quick-fix` marked `[x]` by hand with a `QF-N` ID that the slice parser cannot read, so it never got Referee trailers and its PR showed red. `.claude/commands/` does not load in cloud threads.
  - Decision: `start-slice.mjs --adhoc` opens a slice in one call after the thread opens its GitHub Issue. It writes an `[IN_PROGRESS]` line with a numeric ID (next free minor under the highest major in the working tree and `origin/main`), colour tag, Target files (fewer than 5), `Issue: #N` and Verify, plus an anchor commit with `Spec-Bypass: on-the-fly Issue #N` trailers. The operator's request is the approval for that slice. It counts toward the one-active-slice limit. It refuses Red tripwire paths, spoke engine paths, main-red and an existing active slice, which all still need `/spec` or a fix first. It closes only through `finish-slice.mjs`. `/quick-fix` becomes a one-file on-the-fly slice that closes `[x]` in the same turn. `QF-N` is retired. Contract: SYSTEM_SPEC 4.A.2 and 4.A.6.
  - Rejected: a new work mode or a softer PLAN LOCK (do-not-build list); IDs derived from issue numbers (they would break the stage numbering); a separate `/slice` slash command as the only way in (commands do not load in threads).
  - Consequences: Slices 18.1 to 18.3 (`.spec/plans/on-the-fly-slices.md`). Only the PLAN LOCK warning text changes. Referee, tripwires, hard blocks, the auto-chain ceiling, main-red and the music-visualizer rule are unchanged. Known risk: two parallel branches can pick the same ID before either reaches `origin/main`. The issue number stays the unique key, and the later branch renumbers its line before merge.
